أريد إضافة نظام مراقبة «دفتر الديون» إلى واجهة لوحة تحكم Admin الموجودة في المشروع.

مهم:
لقد قمت مسبقًا بإنشاء جداول دفتر الديون في قاعدة البيانات، فلا تقم بحذفها أو إعادة إنشائها أو تغيير بنيتها إلا إذا كان ذلك ضروريًا وبعد التحقق من المخطط الحالي.

الجداول والبيانات الأساسية هي:

1. debt_accounts
- id
- driver_id
- consumer_id
- debt_ceiling
- balance
- status
- created_at
- updated_at

2. debt_entries
- id
- account_id
- order_id
- amount
- created_at

كما تمت إضافة payment_method إلى جدول orders، وقيمة الدفع بالدين هي:
payment_method = "debt"

المطلوب:

1. دراسة بنية Admin Dashboard الحالية والالتزام بنفس:
- نظام تسجيل الدخول وصلاحيات Admin.
- تصميم الواجهة الحالي.
- المكونات المستخدمة.
- أسلوب جلب البيانات وإدارة الحالة.
- اللغة العربية واتجاه RTL.
- التصميم المتجاوب للهاتف والكمبيوتر.

2. إضافة قسم جديد في لوحة الإدارة باسم:
"دفتر الديون"

3. إنشاء مسارات API خاصة بالإدارة، مثل:
- GET /api/admin/debt-book
- GET /api/admin/debt-book/:accountId
- GET /api/admin/debt-book/entries

يجب أن تكون هذه المسارات محمية بصلاحيات Admin فقط، وألا تعتمد على معرفات السائق أو المستهلك القادمة من الواجهة لتحديد الصلاحيات.

4. في صفحة قائمة الديون، اعرض جدولًا أو بطاقات تحتوي على:
- اسم السائق ورقم هاتفه.
- اسم المستهلك ورقم هاتفه.
- إجمالي الدين الحالي.
- سقف الدين.
- المبلغ المتبقي من السقف.
- حالة الحساب.
- عدد الطلبات المسجلة بالدين.
- مجموع المشتريات بالدين.
- تاريخ إنشاء الحساب.
- آخر تحديث.

5. أضف بطاقات إحصائية أعلى الصفحة تعرض:
- إجمالي حسابات الدين.
- عدد المستهلكين الذين لديهم دين فعلي.
- إجمالي الديون المستحقة.
- إجمالي قيمة عمليات الشراء بالدين.
- عدد الطلبات المسجلة بالدين.

6. أضف البحث والتصفية حسب:
- اسم السائق.
- اسم المستهلك.
- رقم الهاتف.
- حالة حساب الدين.
- وجود رصيد دين أكبر من صفر.
- الفترة الزمنية.
- تجاوز أو الاقتراب من سقف الدين.

7. عند الضغط على حساب دين معيّن، افتح صفحة أو نافذة تفاصيل تعرض:
- معلومات السائق.
- معلومات المستهلك.
- الرصيد الحالي.
- سقف الدين.
- المبلغ المتبقي.
- حالة الحساب.
- قائمة كل المشتريات أو الطلبات المسجلة بالدين.

تفاصيل كل عملية يجب أن تعرض:
- رقم الطلب.
- قيمة العملية.
- طريقة الدفع.
- كمية المياه.
- عدد البراميل.
- حالة الطلب.
- تاريخ العملية.
- تاريخ إتمام التوصيل إن كان متوفرًا.

8. أضف ترتيبًا للعمليات:
- الأحدث أولًا.
- أو حسب قيمة العملية.
- أو حسب أكبر رصيد دين.

9. يجب أن تكون البيانات حقيقية من قاعدة البيانات، بدون بيانات وهمية أو ثابتة.

10. يجب عدم السماح لـ Admin بتعديل أو حذف عمليات الدين في هذه المرحلة؛ المطلوب حاليًا هو الاطلاع والمراقبة فقط، مع إبقاء أي عمليات حساسة محمية وغير قابلة للتنفيذ من الواجهة.

11. يجب التأكد من أن:
- الحسابات ذات الرصيد صفر تظهر في قائمة الحسابات إن كان ذلك مفيدًا للمراجعة، مع إمكانية تصفية الحسابات ذات الدين الفعلي فقط.
- المستهلك الذي لديه عدة طلبات بالدين يظهر في حساب واحد، وليس كسجلات مكررة.
- الرصيد الحالي يساوي مجموع عمليات الدين المرتبطة بالحساب.
- لا تظهر بيانات حسابات السائقين أو المستهلكين غير المصرح بها.
- لا يتم كشف أي رموز جلسات أو مفاتيح سرية في الواجهة أو السجلات.

12. أضف حالات الواجهة التالية:
- تحميل البيانات.
- عدم وجود حسابات ديون.
- عدم وجود نتائج بعد التصفية.
- خطأ في الاتصال بالخادم.
- حساب بدون عمليات دين.
- حساب تجاوز أو اقترب من سقف الدين.

13. بعد التنفيذ:
- شغّل فحص TypeScript.
- شغّل بناء الواجهة والخادم.
- اختبر صلاحيات Admin.
- اختبر قائمة الديون.
- اختبر فتح تفاصيل الحساب.
- اختبر ظهور الطلبات والمشتريات بالدين.
- اختبر البحث والتصفية.
- تأكد من عدم كسر أي جزء موجود في لوحة الإدارة.
- لا تستخدم بيانات تجريبية دائمة ولا تترك أي سجلات اختبار في قاعدة البيانات.

قبل البدء، افحص الملفات الحالية الخاصة بـ:
- Admin Dashboard.
- نظام صلاحيات Admin.
- مخطط قاعدة البيانات.
- مسارات الطلبات.
- مسارات دفتر الديون الحالية.

ثم نفّذ الإضافة داخل البنية الحالية للمشروع، مع الحفاظ على التصميم والوظائف الموجودة.
